# 生图分辨率保护与告警

## 行为与检测口径

后台“系统设置 → 网关服务 → 生图分辨率保护”独立控制成功成品的质量检测。默认关闭；开启后，真实成品像素面积严格低于目标面积的75%时记一次异常，连续异常默认1次即触发600秒冷却。比例阈值、连续次数、冷却时长和邮件告警均可配置。

例如明确请求 `2048×2048`，返回 `1024×1024`，实际面积为目标的25%，触发异常；恰好75%不触发。这里检查明显缩水，不要求每个像素精确一致，也不把更大的成品判为异常。

OpenAI 使用实际规范化发送的尺寸，保留模型专用映射：GPT Image 2系列的4K方图 `2880×2880`、3:2的 `3504×2336` 均按其真实目标判断，不能统一要求长边达到4096。Gemini按受支持模型和比例的目标面积检查，未指定比例时使用该档位最小目标面积。未知规格、没有明确目标的auto、尺寸无法解码均记录为无法判定，不据上游JSON的 `size` 声明或计费档位推断异常。

同一请求返回多图时，任一张明确缩水即计一次异常；全部图片均可测且合格才清零连续次数。流式预览图不参与，最终图片按输出标识去重。GIF使用画布尺寸，SVG使用现有安全校验后的根尺寸。

### 不同宽高比的4K判定

4K是模型的请求档位，不能一律当作 `4096×4096`，也不能只检查长边或短边。下表是本项目GPT Image 2/2.5系列当前转发映射与Gemini 3 Pro Image、3.1 Flash Image的目标尺寸，均以宽×高表示：

| 请求比例 | GPT Image 2/2.5系列4K | Gemini 3 Pro / 3.1 Flash Image 4K |
|---|---|---|
| 1:1 | 2880×2880 | 4096×4096 |
| 16:9 | 3840×2160 | 5504×3072 |
| 9:16 | 2160×3840 | 3072×5504 |
| 4:3 | 3264×2448 | 4800×3584 |
| 3:4 | 2448×3264 | 3584×4800 |

Gemini尺寸于2026-11-13按[Google官方尺寸表](https://aistudio.google.com/docs/image-generation#aspect-ratios-and-image-size)重新逐项核对。GPT Image映射见 `backend/internal/service/openai_image_dimensions.go` 的模型尺寸规范化逻辑；质量保护读取最终发送请求中的 `size`，即使客户端模型经渠道映射，也不拿另一模型的4K表覆盖已发送的明确宽高。

判定公式为 `(实际宽×实际高) / (目标宽×目标高)`，严格小于75%才异常。横竖交换的面积相同，轻微尺寸偏差不会因此误触发；该保护检测降档，不负责验证构图方向或宽高比是否完全一致。明确像素请求也按其真实发送尺寸检查，例如请求 `3840×2160`、返回 `1920×1080` 的面积比为25%，会触发。请求尺寸本身仍须符合所选模型原有的输入校验。

## 交付和调度边界

- 当前结果继续正常交付并沿用现有计费；不会因检测而自动降价、退款、失败或重新生成。
- 冷却范围为账号ID、客户端请求模型、请求档位的组合，同步与持久异步共享。其他账号、模型、档位和普通文本请求不受该质量冷却影响。
- 开启保护后，候选筛选及实际发送前准入都会避让匹配冷却；同模型4K的16:9、9:16等比例共享该档位冷却。候选全部冷却时沿用入口既有的无可用/等待流程，不强行选回冷却账号。已经通过最后准入、正在上游执行的请求不追溯取消。
- 质量冷却独立于连续请求失败熔断。普通HTTP200及其他规格成功不会提前解除；同一冷却周期内并发或迟到结果不反复延长截止时间。
- 冷却到期自动恢复。关闭主开关后停止新检测并忽略存量质量冷却，原截止时间仍保存；重新开启时未到期记录继续生效。修改时长只影响新周期。
- 账号列表状态列直接显示未到期的质量冷却模型、档位和截止时间，点击或通过更多菜单“生图分辨率冷却”进入详情，查看尺寸证据并逐周期确认提前解除；不修改账号持久调度开关或其他限速。保护关闭时保留记录并显示关闭提示，不将其描述为正在阻止调度。
- URL结果只下载已有成品，不再次POST生图。异步复用现有下载和暂存恢复；同步URL由2个后台工作线程检查，每次任务最长30秒，继续使用现有下载安全和资源上限。无法下载或队列繁忙不把成功请求改为失败。

## 管理接口

`GET/PUT /api/v1/admin/settings/image-resolution-guard` 使用现有管理员认证和审计。PUT仅接受配置字段：

```json
{
  "enabled": false,
  "min_area_percent": 75,
  "failure_threshold": 1,
  "cooldown_seconds": 600,
  "email_enabled": true,
  "recipients": []
}
```

`min_area_percent` 和 `failure_threshold` 均为1～100整数；`cooldown_seconds` 为10～86400整数。`recipients` 为邮箱字符串数组，空数组使用首个有效管理员当前绑定邮箱，填写后使用专用列表。GET另返回实际收件人、来源、SMTP配置状态和告警提示；这些只读字段不回传PUT。

账号质量冷却使用独立接口：

```http
GET /api/v1/admin/accounts/:id/image-resolution-cooldowns
POST /api/v1/admin/accounts/:id/image-resolution-cooldowns/:cycle_id/clear
```

列表返回 `items` 数组，解除按账号及周期匹配，避免清除后来建立的另一个周期。既有 `clear-rate-limit` 不替代此操作。

管理员账号列表及单账号运行时响应另外带 `image_resolution_guard: { enabled, cooldowns }`。只对当前页账号ID做一次批量查询，不为每行重复请求；冷却变化纳入账号列表ETag。成功读取且无冷却时 `cooldowns` 为 `[]`，读取失败时省略整个字段，不把查询失败当作已恢复。该字段不加入普通用户接口。

## 持久化与邮件

质量状态和幂等观察事件由PostgreSQL保存，达到阈值时在同一事务中开启冷却并建立待发告警。Redis仅用于配置通知和冷却缓存；缓存未命中回源数据库。配置通知丢失时最多5秒回源校正，正命中冷却缓存最多2秒，避免清除时缓存故障导致长时间残留阻断。异步预期规格在清理完整请求前保存，以便结果下载恢复后继续检测。

手动解除成功后删除共享Redis缓存，正常情况下即可恢复参与调度；若删除失败或与旧查询回填并发，最多等待2秒正缓存过期。Redis失败仍查询数据库；数据库或配置读取本身失败时沿用现有网关熔断的放行降级行为，不能把这一异常状态描述为已确认没有冷却。

终态质量事件保留7天并按小时分批清理，待发/认领中的邮件及仍在冷却的周期受到保护。它不修改原有图片文件、任务或账单的保留策略。

每轮冷却产生一条邮件事件，收件人分别记录投递进度；初次发送失败后等待1分钟、5分钟再尝试，总计最多3次，租约过期后可恢复。关闭主开关或邮件开关后跳过尚未发送的告警。SMTP不可用或没有有效收件人时后台显示提示，冷却仍独立生效。

邮件包含账号、模型、请求规格、实际宽高、像素比例、任务/请求ID和冷却截止，不包含提示词、图片URL或密钥。SMTP接受邮件与数据库记录成功之间无法形成原子事务；进程在这一窗口崩溃时仍可能重复发送，不承诺绝对仅投递一次。
