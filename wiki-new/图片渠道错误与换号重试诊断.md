# yottsuno 图片渠道错误与换号重试诊断

诊断日期：2026-10-05。用户明确授权登录 `40.160.139.185` 查看近两天 yottsuno 渠道的错误和自动换号行为。本轮仅只读检查生产，未部署、重启、修改配置或业务数据，未重放生图任务；登录口令和上游凭据不写入文档。

## 结论（生产诊断基线）

yottsuno 两个 GPT 图片账号的大部分终态失败，被上游以 `HTTP 400` 返回，检查时生产网关把它们作为终止错误。尤其是 `invalid_request_error / upstream_text_reply` 携带的中文生成失败和限流文案，没有命中当时可换号的 400 判定；Worker 的普通上游重试和图片账号熔断也排除这一类 400。因此，即使还有其他可选账号、重试额度未耗尽，也会直接结束任务。

换号机制在可识别错误上确实运行：同一时间窗口内，账号 2 有 15 次、账号 3 有 1 次 `openai.images.upstream_failover_switching` 日志。`retry_count=0` 也不能单独证明没有换号：该计数记录 Worker 的持久化重排队，同一次网关调用内的账号切换不增加它。

- 账号 3：同类终止错误日志 122 次，其中 `upstream_text_reply` 31 次、`bad_request` 89 次、`image_request_error` 2 次；换号 1 次。

## 为什么配置了重试仍不触发

生效配置来自 PostgreSQL `settings.key=image_storage_config` 的 `async_image`，管理端已保存时不以 `config.yaml` 的同名项为准：参考图重试 2、普通瞬时上游重试 3、容量重试 3、总重试 16；图片账号熔断已开启，连续失败阈值 5，冷却 600 秒。账号 2/3 开启池模式，同账号重试次数为 3，未自定义重试状态码，所以使用默认 `[401,403,429]`。这些额度均不表示任意错误都会重试。

1. [OpenAI 上游错误判定](../backend/internal/service/openai_gateway_upstream_errors.go) 的 `shouldFailoverOpenAIUpstreamResponse` 会识别认证、真实 HTTP 429、5xx，以及少数 400 的英文过载/处理中错误。异步图片补充函数 `isOpenAIAsyncAccountFailover400` 只检查 message 中的 `invalid request` / `invalid_request`，并排除参考图拉取错误。生产这批错误的 type 虽是 `invalid_request_error`，但 message 是中文生成失败或限流，不能命中这个只看 message 的函数。
2. [图片上游错误返回](../backend/internal/service/openai_images_responses.go) 将未触发换号的响应写为 `OpenAIImagesUpstreamError`；`IsOpenAIImagesRetryableUpstreamError` 只把 HTTP 500 及以上视为服务器失败。[图片 Handler](../backend/internal/handler/openai_images.go) 因此记录 `openai.images.upstream_user_error` 并返回，未进入后续 `UpstreamFailoverError` 的换号循环。
3. [持久 Worker](../backend/internal/handler/durable_async_image_worker.go) 的普通瞬时重试仅接受 HTTP 500/502/503/504/529；未命中参考图或容量分类的 400 最终直接落为 `upstream_failed`。中文字样「速率限制」不会自动转换为 HTTP 429。
4. [图片账号熔断分类](../backend/internal/service/image_account_circuit_breaker.go) 对 `OpenAIImagesUpstreamError` 仅接受 HTTP 408/429/401/403/5xx，排除 400。因此这些 400 不增加连续账号失败计数。池模式还会在 [默认账号状态处理](../backend/internal/service/ratelimit_service.go) 中记录 `pool_mode_error_skipped`，避免默认停用账号。

GPT 图片组 11 使用 `model_resolution` 账号池，查询时相应池仍有账号 24/26/35 等可调度候选；现有绑定也允许账号 2 不通过默认分组绑定参与调度。因此这批终止 400 的主因是错误没有被判为可切换，并非全组只剩 yottsuno 一个账号。各池具体可用账号仍随模型和清晰度变化，不能把全组账号列表直接当作每个请求的候选集合。

## 香蕉渠道的另一种情况

账号 12 在同一窗口触发 `gateway.failover_switch_account` 860 次：HTTP 503 有 794 次、500 有 40 次、504 有 25 次、403 有 1 次。这条 Gemini 链路的换号实际在执行。

北京时间 `2026-10-04 17:41:40`，该账号收到 HTTP 403「预扣费额度失败」，上游报告剩余额度约 0.023202 美元、需预扣 0.056000 美元，随后出现 `account_disabled_auth_error`；检查时其状态为 error 且不可调度。该余额错误与 GPT 图片账号的终止 400 是两个不同原因。

## 后续修复范围（诊断时建议）

- 优先给异步图片路径中明确的限流/过载语义补充分类，把实际为账号容量不足、却返回 400 的错误纳入换号和账号健康判定；结合 provider type/code/message，避免只凭 400 或 `invalid_request_error` 泛化重试。
- 通用「未能生成图片」需要向上游确认可重试语义和计费结果，再决定是否有限换号；保留内容拒绝、缺参考图、明确禁止再生成、未知执行结果的停止边界。
- 增强 OpenAI 终止错误的账号尝试审计：当前部分 failed 尝试只有 error 字符串，缺 status_code/provider_error_code，完整错误 type/code 只能从日志补查。任务详情宜分别展示 Worker 重排队次数、账号尝试和请求内切换，减少把 `retry_count=0` 误读为完全没有尝试。
- 本轮未实施上述代码或生产配置修改，未回填历史任务。改变策略后的本地回归、真实上游计费与生产验收属于后续工作。
