# 对象存储、参考图与保留策略

## 存储模型

图片对象存储拆成两套配置，避免异步短生命周期桶误删广场资产：

| 配置段 | 用途 |
|---|---|
| `image_storage` | 异步生图结果 / SC 参考图（可设一天后生命周期删除） |
| `image_durable_storage` | 投稿 sync、ImportBytes、广场持久化（默认本机磁盘，可改独立 OSS 桶） |

`image_durable_storage.backend`：

- `local`（默认）：写入 `{pricing.data_dir}/image_durable`（或 `local.data_dir`），`provider=local`
- `oss`：使用 `image_durable_storage.oss.*` 独立桶，**禁止**回退到 `image_storage`
- `local.shared=false`（默认）表示单实例本机盘；多实例必须使用 OSS，或显式设置 `shared=true` 并填写所有实例都能访问的绝对 `local.data_dir`。共享目录不应使用相对路径。

异步侧支持：

| provider | 厂商/用途 |
|---|---|
| `qiniu` | 七牛云 Kodo 的 S3 兼容接口 |
| `aliyun` | 阿里云 OSS 的 S3 兼容接口 |
| `tencent` | 腾讯云 COS 的 S3 兼容接口 |
| `custom_s3` | 兼容既有 AWS S3、R2、MinIO 和其他 S3 服务 |

厂商模式提供 endpoint 预设，也允许显式高级覆盖；七牛/阿里/腾讯必须填写有效 region。完整模板见 `deploy/config.example.yaml` 的 `image_storage` 与 `image_durable_storage`。

保存结果返回稳定元数据：

```text
provider / bucket / object_key / content_type / bytes / checksum / width / height
```

迁移 `186_ZJ_image_library_and_plaza_moderation.sql` 将生成结果元数据规范化到 `image_storage_objects`。`async_image_results` 继续引用异步桶对象；投稿 sync / ImportBytes 写入 durable 后端。历史 `from-task` 资产仍可读异步桶。迁移 `187_ZJ_async_image_upload_reservations.sql` 另外为 SC 输入建立 admission reservation、attempt 与 URL alias 事实表。

数据库不保存会过期的预签名 URL。查询时若配置对应后端的 `public_base_url`，生成公开 CDN 地址；本地 durable 对象由查看接口直接流式返回。SC 和站内 JSON 查看接口的 `expires_at` 必须对应本次实际签名到期时间。

公开广场 `GET /api/v1/image-plaza/:id/content`（无登录也可访问）对浏览器开放短缓存：本机流式响应 `public, max-age=3600`；OSS 临时重定向 `public, max-age≤300`（且短于签名剩余有效期）。个人图库 `/view` 仍为 `private, no-store`。列表返回的稳定相对路径与灯箱共用同一 URL，缩略图加载后再次打开可命中浏览器磁盘缓存。

## 配置和连接探测

- 异步 `image_storage`：后台保存的数据库设置优先于 config/env，并可用于即时更新运行参数。
- `image_durable_storage`：首期以 config.yaml / 环境变量为准（不与异步设置共用）。
- 启用异步存储配置前必须真实执行小对象上传、HEAD/读取验证和删除。
- 任一步失败都不能把配置保存为可用状态；失败时返回 **400** 与可读中文说明（不再只显示 `internal error`）。
- 后台入口位于「数据备份 → 异步生图对象存储」，API 为 `/api/v1/admin/backups/image-storage`，测试接口为 `/api/v1/admin/backups/image-storage/test`。同一设置页包含后端选择、凭证与异步/图库运行参数（不含 durable 独立桶）。
- 生产凭证优先通过 `IMAGE_STORAGE_ACCESS_KEY_ID`、`IMAGE_STORAGE_SECRET_ACCESS_KEY` 或受控密钥系统注入，不要提交到 Git。

### 本机目录（`backend=local`）

适用于自托管、不想接 OSS/Superbed 的异步结果与 SC 参考图。与 `image_durable_storage.backend=local`（广场/投稿持久化）是**两套配置**，不要混用字段。

| 字段 | 说明 |
|---|---|
| `local.data_dir` | 异步结果与参考图写入根目录。留空时服务端自动解析（见下） |
| `local.local_url` | 对外 CDN/静态站根地址；查询 `data[].url` 优先用 `local_url/object_key` |
| `public_base_url` | 对象 CDN 根（无 `local_url` 时参与拼公开链） |
| `async_image.public_base_url` | 无 `local_url`/对象 CDN 时，用于站内 HMAC 签名下载（`/v1/images/local/...`） |

**目录回落规则**（`data_dir` 留空时）：

```text
1. 若环境变量 DATA_DIR 已设置，且 pricing.data_dir 为空或为 "./data"
     → {DATA_DIR}/data/image_storage
2. 否则
     → {pricing.data_dir}/image_storage（pricing 默认 "./data"）
```

二进制发行版常见：`DATA_DIR=/opt/sub2api`、WorkingDirectory=`/opt/sub2api` → 默认目录 **`/opt/sub2api/data/image_storage`**。保存成功后，管理端会把解析后的绝对路径写回表单，便于核对。创建目录时请求 `0700`/`0600`，但 `chmod` 失败（常见于目录属主非服务用户、systemd `NoNewPrivileges`）不再阻断探测与上传，只要进程可写即可。

**访问地址**：自托管推荐**留空 `local_url`**，填写「站点/API 公开地址」或运行参数里的 `async_image.public_base_url`（与反代到本服务的 HTTPS 域名一致）。服务会返回 `https://你的域名/v1/images/local/{object_key}?exp=&sig=`，由本进程签名下载。

不要把普通网站首页域名填成 `local_url`：那样会生成 `https://站点/images/...` 静态路径，站点并没有挂载 `data_dir`，浏览器会 **404**。只有已用 Nginx/CDN 把该域名映射到本机目录时才填 `local_url`。

**常见保存失败原因**：

| 现象 | 处理 |
|---|---|
| 无法创建或写入本机存储目录 | 确认 `data_dir` 对运行用户可写；systemd 下目录宜在 `ReadWritePaths` 内（如 `/opt/sub2api/...`） |
| `chmod ... operation not permitted`（旧版本） | 已改为尽力 chmod：只要可写即可保存；升级含本修复的版本后重试。可选：`chown -R sub2api:sub2api /opt/sub2api/data` |
| 本机存储目录未配置 | 填写 `data_dir`，或确认 `DATA_DIR` / `pricing.data_dir` 可用 |
| 异步生图已启用但必填项不完整 | 补全上述访问地址或凭证 |

**冒烟/单测**（2026-08-14）：`ImageStorage`/`LocalImage` 相关 Go unit、`BackupView.spec.ts` 已通过；部署后仍建议在管理端点一次「测试连接」再保存。

## 历史对象与存储后端切换

全站仍只有**一套当前**图片存储身份（`oss` / `superbed` / `local`）。`2026-08-14` 起，后台保存设置时**不再**因库内仍有活跃对象而拒绝切换后端；配置保存后立即热加载生效。

风险与建议：

1. 切换后新上传写入新后端；旧 `image_storage_objects` / `async_image_results` 仍指向旧定位，查看、签名或清理可能失败。
2. 生产切换前应先在「图片管理 → 清理」执行 `all`（清理全部）或至少 `async_results`，再改后端。
3. 按历史身份并行解析多套凭证的 resolver / 对象迁移工具仍是 P1。

身份定位字段（用于理解“什么叫换了后端”，不再用于拒绝保存）：

```text
oss: provider / bucket / endpoint / region / force_path_style
local: data_dir
superbed: categories / upload_url
```

`local_url`、对象 CDN、`async_image.public_base_url` 等公开访问根地址不是定位身份，可随时修改。保存本机/图床时会清空另一套后端残留字段，避免表单里的 OSS `region=auto` 等噪声干扰。

保存对象存储 Secret 或 Superbed Token 前必须配置固定 `TOTP_ENCRYPTION_KEY`（或 `totp.encryption_key`）。

## 管理端存储清理

清理任务 API：`POST /api/v1/admin/image-library/cleanup-jobs/preview` 与 `POST /api/v1/admin/image-library/cleanup-jobs`。

| scope | 覆盖 |
|---|---|
| `all` | 图库未 purge 项 + 异步任务结果 + 无引用存储对象 + SC 输入对象 + 上传 intent/reservation 残留 |
| `async_results` | `async_image_results`（及可安全删除的对应对象） |
| `expired` | 已过期且未 purge 的图库项 |
| `deleted` | 已软删且未 purge 的图库项 |
| `user` | 指定 `filters.user_id` 的图库项 |

旧版仅图库三档时，异步任务生成的图片不会出现在预览命中里；`async_results` / `all` 已修复该盲区。必须先预览再执行；删除不可恢复。

## 参考图安全

BB 远程参考图与 SC 上传都经过限制：

- 只允许 HTTPS 或受限 data URI。
- 初始 DNS、实际 dial IP 和每次重定向重新检查地址。
- 拒绝内网、回环、链路本地和保留网段。
- 校验声明 MIME、响应 MIME 和实际解码格式。
- 默认单图上限 32 MiB、硬上限 64 MiB、总超时 30 秒、最多 3 次重定向。
- 当前解码像素上限为代码默认 8000 万像素，尚未开放运行时配置。
- SC 上传在 multipart body 前先做 PostgreSQL rolling-rate admission，在图片解码/OSS 前再做幂等与 Key 级字节 reservation；数据库故障时 fail closed。
- SC 上传对象绑定 API Key 所有权，原签名 URL和每次重签 URL 只保存 SHA-256 hash/alias；已知失效或跨 Key alias 不会降级为普通外部 URL。alias 注册对输入对象加行锁，每对象最多 128 个，过期记录继续作为所有权墓碑。
- OSS Put 默认超时 300 秒，运行时最大规范化为 600 秒，严格短于 15 分钟 reservation lease。
- failed/stale object intent 第一次删除成功后仍保留并占用 Key 容量；至少十分钟后二次删除成功才移除恢复事实。
- 文件名净化后只作为元数据，不进入服务端生成的 deterministic object key。

活动任务通过 `async_image_task_inputs` 引用输入对象，清理器不会提前删除仍被活动任务使用的参考图。

## 对象前缀与日期分区

`image_storage.prefix` 是根前缀，参考图、生成结果和连接探测对象在不同子前缀下保存。对象 key 由服务端生成，不能拼接下游提供的原始文件路径；文件名只作为脱敏元数据。

服务端用 `ImageObjectDatePartition(now)`（UTC `YYYY/MM/DD`）分区。图库会将相对路径交给 durable storage 的对象键解析器：local 固定使用 `library/` 命名空间，OSS 使用 `image_durable_storage.oss.prefix`（例如 `library/`）作为根前缀。prefix 只能是安全的正向路径片段，不能包含 `..` 或反斜杠。例如：

```text
library/{userId}/2026/07/22/{uuid}.png
{prefix}/results/2026/07/22/{taskId}/001.png
{prefix}/inputs/2026/07/22/{apiKeyId}/{uploadId}.png
```

分区只影响对象路径组织，不改变保留天数、引用计数或删除规则。

## 默认保留期

| 数据 | 默认值 | 配置 |
|---|---:|---|
| SC 参考图 | 24 小时 | `async_image.input_retention_hours` |
| 上游成功 staging | 最长 24 小时 | 代码恢复安全窗 |
| 任务记录 | 90 天 | `async_image.task_retention_days` |
| 生成结果对象 | 90 天 | `async_image.result_retention_days` |
| 动态签名 | 3600 秒 | `async_image.signed_url_expiry_seconds` |
| 私有图库资产 | 90 天 | `image_library.retention_days` |
| 图库动态签名 | 3600 秒 | `image_library.signed_url_expiry_seconds` |
| 本机延期投稿 blob / 本地个人图库 | 30 天、最多 100 条、合计不超过 200 MiB | 浏览器 IndexedDB（`personalGalleryStore`，仅 Blob，不持久化 preview data URL） |

异步任务保留清理循环与图库维护 Worker 是两套执行器：异步清理当前约每 15 分钟运行、单批 100 条、claim 租约 30 分钟；图库维护当前约每 10 秒扫描一次，使用两分钟 stale 阈值和 30 秒心跳。两者删除同一对象前都必须检查统一引用。

SC 输入保留最长 720 小时。上传前持久化的 object intent 也由异步 retention 清理：stale reserved 或 failed reservation 会被 claim，按稳定 intent 至少间隔十分钟执行两次 OSS Delete；第一次仅记录删除时间并释放 claim，第二次成功才移除 reservation。完成输入对象删除后，已完成 reservation 的短期幂等墓碑仍可返回 `409`，防止旧键重新创建对象。

异步生成结果使用另一类 `async_image_result_upload_intents`。Worker 在 PUT 前固定 provider、bucket、object key、MIME、字节和 SHA-256；部分成功时 intent 保留，任务结果清单落库后同事务删除。过期清理先检查异步结果、图库和有效投稿引用，只有无活动引用才删除 OSS。该表由迁移 `189_ZJ_async_image_result_upload_intents.sql` 创建。管理员 `all` / `async_results` 清理会主动删除结果行并尝试回收对象。

## SC 上传 admission 配额

| 配置 | 默认值 | 最大值 |
|---|---:|---:|
| `async_image.upload_per_minute` | 20/Key/分钟 | 1000/Key/分钟 |
| `async_image.max_input_bytes_per_key` | 1 GiB | 100 GiB |
| `async_image.download_max_bytes`（单图/请求有效图片负载） | 32 MiB | 64 MiB |
| `async_image.download_max_pixels` | 40 MP | 80 MP |
| `async_image.max_reference_images` | 8 张 | 16 张 |
| `async_image.max_reference_total_bytes` | 64 MiB | 256 MiB |
| `async_image.max_reference_total_pixels` | 80 MP | 320 MP |
| `async_image.input_retention_hours` | 24 小时 | 720 小时 |

字节额度是“未过期输入对象 + 活跃 reservation”的总和；不是只在上传完成后统计。第一阶段 attempt 在读取 body 前记账，恶意无效 body 也无法绕过限频。

## 图库配额

| 配置 | 默认值 |
|---|---:|
| 每用户最大条目 | 1000 |
| 每用户对象总量 | 5 GiB |
| 单图最大字节 | 20 MiB |
| 单图最大像素 | 40 MP |
| 导入限频 | 20 次/分钟 |
| 投稿限频 | 10 次/分钟 |

图库配额只决定是否允许新的归档/导入。已经成功的模型请求不能因为归档失败而改成生成失败，也不能因此重新调用上游或重复计费。实时工作台在本地图库写入失败时保留当前结果 data URL，并提示用户下载或重试投稿。

浏览器侧清理按 `userId` 隔离，不会因另一个用户在同一浏览器保存图片而淘汰当前用户记录；条数、30 天保留期和 200 MiB 字节预算分别参与清理。

## 共享对象删除规则

OSS 删除前必须确认对象不再被以下任一记录引用：

- 活动 `async_image_results`。
- 未软删除的 `image_library_items`。
- `pending_review/published/admin_hidden` 且未过期的投稿。

删除流程使用 `image_storage_objects.state = active/deleting/deleted`。先 claim，再删除 OSS，最后标记对象和业务记录；数据库更新失败时 stale object recovery 必须能继续收敛。异步结果保留清理完成时也应同步更新统一对象状态，避免统计仍把已删除对象计为 active。

## 容量注意事项

上游成功图片会短期以 `BYTEA` 存在 PostgreSQL staging 中，以保证进程重启不重新生成。大图并发会增加数据库容量、WAL、备份和复制压力。生产环境应监控：

- `async_image_staging_objects` 总字节和最老记录年龄。
- PostgreSQL 磁盘、WAL 和副本延迟。
- OSS 上传失败率和延迟。
- `storage_failed` 数量与清理积压。
- 输入、结果和任务的过期清理延迟。
- `image_storage_objects` 中长期停留在 `deleting` 的数量和年龄。
- 图库条目/唯一对象字节、待处理 Outbox、清理任务和旧迁移积压。

`2026-08-14`：管理端清理已覆盖异步任务结果与全量清理；存储后端切换不再被活跃对象拒绝；**本机目录**保存失败改为返回可读 400（目录回落、`DATA_DIR` 对齐、前端错误展示）。真实厂商 delete/HEAD 幂等与多凭证并行解析仍为 `PENDING`。
