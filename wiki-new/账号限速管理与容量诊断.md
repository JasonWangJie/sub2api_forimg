# 账号限速管理与容量诊断

本页描述2026-11-13本地增强。管理员可以查看异步任务的容量失败原因，并通过带状态校验的预览提前解除账号冷却。尚未部署；验证结果以[开发台账](../开发台账.md)为准。

## 容量不足时看什么

在后台异步生图任务详情查看“容量不足诊断”。新任务发生本地容量失败时，记录该次请求的分组、模型、清晰度和观察时间，以及以下分开的观察阶段：

| 来源 | 含义 |
|---|---|
| 实际筛选结果 | 调度路径实际记录的排除项，例如模型不支持、模型限速、本次已排除、运行时阻断或配额约束；未覆盖的细分原因显示未知，不推断 |
| 并发准入结果 | 实际获取账号并发槽时观察到的容量不足；获取失败的其他原因保持未知 |
| 账号池状态快照 | 容量失败后读取当次匹配池的数据库状态，辅助查看关闭调度、非正常、过期、平台不匹配、限速、过载及临时不可调度；不等于更早筛选时的状态 |
| 未取得诊断信息 | 读取超时、适配器缺少能力或没有可观察数据；不伪造确定原因 |

不同阶段可能包含同一账号，数量不能相加。池快照通过基础状态不代表支持模型、有空闲并发或一定可选；最早恢复时间只是对应限制的截止，不保证账号届时满足所有条件。模型/清晰度池可以引用默认分组关联以外的账号，不能只检查`account_groups`。

正常成功路径不增加诊断数据库查询。选号时仅登记匹配池描述和实际观察；容量失败分支统一使用总计300毫秒的采样预算，最多8个池描述、16条观察、每池最多256行、每个原因最多20个账号ID。候选总数与截断标记分开，记录只包含运行元数据，不读取凭据、提示词或参考图内容。诊断持久化失败不改变原任务调度、错误码或重试行为。

记录存入独立`capacity_diagnostic`任务事件，仅管理员详情返回`events[].capacity_diagnostics`；普通用户过滤该事件。历史任务没有新诊断时不回填，不把目前账号状态当成历史证据。新增事件不代表又调用了一次生图渠道。

## 配置时长与提前解除

- 默认策略仍在“系统设置 → 网关服务 → 429 默认回避”：默认开启5秒，启用时1～7200秒，仅用于后续无法识别有效重置时间的429响应。上游明确恢复时间及平台专用规则仍各自生效。
- 账号管理“更多 → 提前解除限速 / 冷却”先加载当前预览，再显示限制及截止时间。确认清除时携带预览版本；状态变化返回409，必须重新加载并再次确认。
- 清除范围为本系统的账号限速、模型限速、Antigravity配额范围、过载、临时不可调度及对应运行时缓存。保留账号状态、手动调度开关、到期策略、凭据和其他配置，不重置供应商额度，不重跑历史任务。
- 数据库限制字段与调度outbox记录在同一事务提交。写入或outbox失败时回滚，两个管理员使用同一预览只有一个能清除原状态；等待锁期间出现新限制会使旧预览失效。数据库提交时连接异常可能导致结果未知，应重新读取状态，不能把所有HTTP错误解释成完全未修改。
- 数据库提交后同步缓存；缓存失败不会把已经提交的清除伪装为回滚。页面保留解除前后摘要，并明确提示同步尚未完成及受影响组件，不提供沿用旧预览再次解除的按钮。
- 菜单和弹窗仅显示期间更新到期状态；提交前再次检查当前时间，全部已到期则不发清除请求。

旧“恢复状态”不再绕过预览清除冷却：有有效冷却时转入预览流程，纯错误恢复仍用于处理错误状态。旧临时不可调度弹窗的解除操作也转到新预览；内部成功请求触发的自动恢复仍有独立语义。

## 管理接口与兼容

以下接口仍受管理员认证和操作审计保护。它们是后台接口，不改变公开异步生图API。

```http
GET /api/v1/admin/accounts/12/rate-limit-state
```

响应`data`包含`account_id`、`version`、`status`、`schedulable`、`active_count`、`truncated`和`restrictions`。限制项包含`kind`、可选模型`scope`及可选ISO截止`until`；旧配额标记可能没有截止。版本只由相关限制与账号身份/状态/调度决定，日常用量更新时间不会使预览无故失效。

```http
POST /api/v1/admin/accounts/12/clear-rate-limit
Content-Type: application/json

{"expected_version":"<复制本次GET返回的version>"}
```

必须先GET取得实际版本，不能使用固定示例值。缺少或格式错误的版本返回400；状态改变返回409 `RATE_LIMIT_STATE_CHANGED`，不执行清除。成功响应`data`为：

```json
{
  "account": {},
  "before": {"version": "…", "active_count": 2, "restrictions": []},
  "after": {"version": "…", "active_count": 0, "restrictions": []},
  "cache_sync": {"status": "synced", "failed_components": []}
}
```

上例仅展示响应结构。`account`通常为最新完整后台账号对象；提交后账号回读失败时为`null`，并以`cache_sync.status=warning`和`account_refresh`反馈，数据库清除仍可能已经提交。其他同步组件包括`temp_unsched`、`openai_403`、`runtime_block`、`scheduler_snapshot`。`before/after`保留同预览结构，摘要最多100条并标记截断。

旧客户端不带版本的清除请求不再允许。旧`DELETE /api/v1/admin/accounts/:id/temp-unschedulable`返回409 `RATE_LIMIT_PREVIEW_REQUIRED`，需迁移到上述预览流程；`POST .../recover-state`在存在冷却时同样要求先预览解除。升级时后台前后端应一起更新，外部管理员脚本也需调整。

## 审计与运行边界

在既有管理员通用审计上增加清除前后版本、数量、限制类型、原截止摘要、状态/调度开关和缓存结果；模型名称及任意内部错误原因不会原样写入审计。成功注明数据库已提交，失败与明确版本冲突分别记录；摘要截断会标记。

数据库事务与Redis/进程缓存不是一个分布式事务。手动清除在数据库操作前观察缓存状态，临时不可调度缓存采用代际令牌条件删除，进程内阻断采用匹配截止与代际条件删除；观察之后新写入的状态保留并提示。无法可靠对应原限制的运行时阻断、现存403计数等状态保守保留，不能当作同步完成。调度账号缓存以失效后回源读取代替读旧值后覆盖写回，同事务outbox负责后续刷新。

这些保护不构成所有进程、Redis和数据库之间的全局原子提交；特别是其他请求先记录内存信号、随后才持久化的窗口仍由原运行时流程处理。缓存异常或状态被保留时应刷新核对，不能持续点击解除替代排查上游限流。

## 本地冒烟复验

2026-11-13建议实施后再次本地冒烟：浏览器15场景、前端63项、限速HTTP与审计10个子场景、真实隔离PostgreSQL的原子清除与池快照、缓存替身验证通过。补充[双平台完整Worker测试](../backend/internal/handler/async_image_capacity_worker_smoke_test.go)，确认无可调度账号时上游调用为0，重试和终态均写诊断事件，普通用户不收到账号诊断；终态重投不增加事件。普通限速解除与独立分辨率冷却的界面兼容也已检查，未发现新业务缺陷。

浏览器API与父账号行使用合成数据，Worker任务/账号仓储为内存替身，审计COPY末端为sqlmock，缓存使用miniredis；这些与独立PG用例共同验证局部链路，不代表生产全链路、真实Redis或供应商验收。未改业务实现、未部署；准确命令、结果及已关闭的本机测试实例见[开发台账](../开发台账.md)。
