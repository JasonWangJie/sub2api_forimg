# 异步生图结果转存与格式兼容

对外接入统一查阅 [异步生图接口文档（新）](../异步生图接口文档new.md)及站内 `/guides/async-image-api` 双语指南：主示例按“文生图、图生图”组织，GIF/SVG 作为输出参数扩展集中说明。本页保留存储实现、格式边界与真实试单证据，不替代接口契约。

## 结果处理流程

异步 Gemini / OpenAI 生图统一使用以下流程：

```text
上游成功响应
  -> 提取图片 Base64 或来源 URL（不在兼容层下载）
  -> Worker 解码或安全下载
  -> 按实际字节完整校验 PNG / JPEG / WebP / GIF，或校验静态安全 SVG
  -> 保存暂存字节、实际 MIME、宽高、checksum 和固定账单命令
  -> 写入上传意图，再上传到当前结果存储
  -> 保存对象引用，幂等结算
  -> 查询时返回本站图片地址
```

2026-10-11 的生产只读快照使用 `local` 后端，目录 `/opt/sub2api/data/image_storage`，`local.local_url=https://file.aiimg.lol`，结果保留期为 2 天；本轮没有重新核对生产配置。成功查询返回形如 `https://file.aiimg.lol/images/results/YYYY/MM/DD/<文件名>.jpg` 的地址。无需增加公共接口、数据库字段或存储配置；静态地址本身没有签名有效期，文件仍由现有保留任务清理。

状态机和上传意图详见 [异步生图架构](异步生图架构.md)，域名和保留策略详见 [对象存储与保留策略](对象存储与保留策略.md)。

## Gemini 来源兼容

私有异步捕获使用 `GeminiGeneratedImage.SourceURL` 保存来源，兼容层只提取，不访问该地址。支持：

| 返回位置 | 处理 |
|---|---|
| `candidates[].content.parts[].inlineData.data` | 图片 Base64、直接 HTTP/HTTPS URL、Base64 编码的 URL |
| `inline_data.data` / `mime_type` | 同上，兼容下划线字段 |
| `fileData.fileUri` / `mimeType` | 提取图片来源 URL |
| `file_data.file_uri` / `mime_type` | 同上，兼容下划线字段 |
| 顶层 `data[].url`，再回退到顶层 `url` | 没有结构化 Gemini 图片时提取来源 |
| `parts[].text` 的完整 URL 或单个 `![描述](URL)` | 没有结构化图片及 URL envelope 时提取来源 |
| 整个响应体为纯 URL、JSON 字符串 URL 或单个 Markdown 图片链接 | 仅私有异步路径兼容 |

同一响应可以包含多张图片，保持结构化 parts 的顺序。结构化图片优先，附带的文本链接和兼容 envelope 不会再计为新图片。同一个 part 同时有 inlineData 和 fileData 时采用 inlineData。声明 MIME 为空或为 `image/*` 的结构化字段作为图片来源候选；其他媒体类型不会自动转成图片。

普通说明文字、拒绝文案中包含的 URL，以及包含多个 Markdown 图片链接的同一文本值，不作为图片结果。同步 Chat Completions 沿用原有转换规则。

OpenAI 原有 `data[].b64_json` / `data[].url` 继续支持，单个 item 同时有两者时仍优先 Base64。URL 下载和实际格式校验与 Gemini 共用 Worker 逻辑。

## 安全下载和实际格式

来源的提取不代表地址已被允许。Worker 使用已有 SSRF 下载器，检查绝对 HTTPS URL、公网 DNS 解析、实际连接地址和每次重定向，并沿用超时、重定向次数、字节与像素限制。初始结果 URL 和重定向 URL 不允许内嵌账号密码；请求不会携带上游 API Key。图片 data URI 直接有界解码，不经过输入对象所有权加载器、参考图缓存或参考图累计预算。

2026-10-11 的生产下载设置只读快照：32 MiB / 张、40,000,000 像素 / 张、60 秒、最多 3 次重定向；这些值由现有 runtime 配置控制，不代表本轮已核实的生产状态。

仅生成结果忽略不准确的声明 MIME / HTTP Content-Type，由完整校验后的实际类型决定保存 MIME 和扩展名。例如，上游声明 `image/jpeg`，实际为完整 PNG 时保存为 `image/png` / `.png`。校验仍包括：

- 字节和像素上限；
- PNG / JPEG / WebP / GIF 容器及结束位置，拒绝尾随内容；SVG 使用独立 XML 与静态内容校验；
- 实际格式、签名和完整图片解码；
- 实际宽高、SHA-256 与对象字节数。

参考图和用户上传继续使用原有 PNG / JPEG / WebP 与声明 MIME 严格校验。MIME 修正不会使 HTML、活动 SVG、损坏图片或超限图片通过。

## 2026-11-06 GIF 与静态 SVG 输出支持（本地实现）

新增 `gif` / `svg` 与 GIF 帧参数仅适用于 OpenAI GPT Image 2.6+ 系列能力；当前代码明确开放的型号是 `gpt-image-2.6-flare` 与 `gpt-image-2.6-sunburst`，后续型号需网关明确支持，不能仅按版本号推定可用。已有 `png` / `webp` / `jpeg` 不受本次新格式的 2.6+ 限定，两款 2.6 模型省略 `output_format` 时默认 `png`。只有 GIF 可携带 `frame_count`（整数 `2`～`16`，默认 `9`）和 `frame_duration_ms`（整数 `20`～`2000` 毫秒，默认 `200`）；SVG 不能携带这两个帧参数。这些规则同时覆盖 `_oa` 持久任务入口及旧式 `/images/generations/async`、`/images/edits/async` 入口；不同任务协议仍用各自查询路径。

GIF 单帧 `size`、帧数与 `n` 共同消耗上游拼图尺寸和总像素预算，不能只检查单帧或帧数合法。示例使用显式 `512x512`，也可用 `auto`；不要直接沿用静态图默认 `1024x1024`。本站接受间隔范围不变，官方上游编码时四舍五入到最接近的 10 毫秒。见 [官方 GIF 指南](https://developers.openai.com/api/docs/guides/image-generation#generate-animated-gif-output)。

SVG 作者模型通过 JSON `svg: {"model": "SVG_AUTHOR_MODEL"}` 或 multipart `svg[model]` 传入，本站不设置默认值，也不自动沿用顶层图片模型。该字段仅在上游启用作者模型选择时条件需要；未启用时省略 `svg`。可选 `svg.reasoning.effort` / `svg[reasoning][effort]` 为作者模型推理档位，提供字符串时须为 `none/minimal/low/medium/high/xhigh/max`，省略或 JSON `null` 不指定档位。非 SVG 输出携带 `svg` 会被拒绝。详情见 [官方编辑接口参考](https://developers.openai.com/api/reference/go/resources/images/methods/edit)。

SVG 示例使用 `n=1` 和占位符 `SVG_AUTHOR_MODEL`，必须由供应商确认可用作者模型后替换。截至 2026-11-06，官方生成指南称编辑端点不支持 SVG，但编辑 API 参考列出 SVG 字段；本站保留其透传能力，不将其视为每个上游的编辑成功保证。当前 SVG 图生图及可用作者模型尚未实测确认。参见 [官方 SVG 指南](https://developers.openai.com/api/docs/guides/image-generation#generate-svg-output)。

生成结果的格式扩展不改变参考图格式限制，不增加重新生图机会，也不改变结果暂存、存储重试与账单幂等行为：

| 成品 | 校验与保存 |
|---|---|
| GIF | 检查完整容器后解码全部帧，最多 16 帧；画布像素与所有帧矩形像素总量均受现有 `DownloadMaxPixels` 限制。保留原始字节、动画时序与循环信息，不转成首帧 PNG。MIME 为 `image/gif`，扩展名 `.gif`。 |
| SVG | 校验为静态 SVG 图形、文字、渐变、裁剪、内部引用及受限静态样式；拒绝脚本、事件属性、`foreignObject`、动画、外部引用、DTD/实体与未知元素/属性。根节点需有效 `width`/`height`（数值或 px）或 `viewBox`，按尺寸限制像素。保留通过校验的原始字节，MIME 为 `image/svg+xml`，扩展名 `.svg`。 |

GIF 的累计解码像素限制可能使高分辨率多帧成品被拒绝，即使单帧尺寸没有超限；应减少帧数或尺寸。SVG 不是任意 XML/HTML 容器，不支持活动内容或外链资源。签名本地结果下载附带 `nosniff`，SVG 另加沙箱 CSP；经外部静态域名或对象存储直连时，以保存前的内容校验保证结果边界。

两种格式仍通过原有 Base64、图片 data URI 或 HTTPS 来源 URL 进入结果链路；按实际格式保存结果元数据，客户端从 `data[].url` 下载原文件，一份 GIF 作为一个结果。格式校验失败走原有 `upstream_invalid_output` / 无效输出处理，不换账号重新生成。代码尚未部署；本地回归和后续真实试单应分开记录，准确命令与结果见 [开发台账](../开发台账.md)。

旧式任务的 `ImageResultUploader` 同步支持 Base64、图片 data URI 和远程 URL 三种结果来源，按生成结果策略校验 GIF/SVG，再用实际 MIME 和扩展名写入存储；旧式任务仍保持自己的响应结构，不改成持久任务的查询协议。

从成功任务保存到图库时，`ImageLibraryService.FromTask` 同样按生成结果策略重新校验，避免合法 GIF/SVG 因静态参考图校验规则被错误隔离；通过校验后沿用原字节与实际 MIME。普通图库导入、参考图和用户上传仍使用原有输入格式限制，不因这一结果入口开放 GIF/SVG。

## 失败与重试边界

已完成的 Gemini 响应解析错误通过私有 capture 交给 Worker，不再转换成可触发换号的 502。Worker 在上游转发结束后处理图片来源；结果下载失败不能进入参考图重试、账号切换或重新生图。

- 明确的无图、非法地址、Base64 / 图片校验失败：`failed / upstream_invalid_output`。
- 下载超时、链接过期等未取得可暂存结果的获取错误：沿用现有 `execution_unknown` 和核对边界，停止自动调用上游。
- 已完整获取并暂存的结果上传失败：只重试存储；幂等对象键由任务提交时间、task ID、图片序号和实际 MIME 确定。
- 上传后计费失败：只重试已有固定账单命令，继续使用 `client:async-image:<task_id>` 幂等键。

错误信息保留 HTTP 状态或失败阶段，不把上游带签名 URL 写入任务错误文案。结果来源 URL 不持久化为公共结果；公共查询只根据本站存储的对象引用生成地址。
