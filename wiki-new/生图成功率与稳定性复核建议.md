## 第一优先级

### 繁忙400进入容量退避和换渠道

35个完整错误为“服务繁忙，请稍后重试”，账号32有15个、33有20个；新版运行期仍25个，全部Worker重试0。部分任务此前已因其他错误换过账号，不能称为完全没有换渠道。样本`asyncimg_01c47b7f5c77c3ce942c8391f8a19b3f`在10-28 10:34:20创建、10:36:35直接failed，事件没有重排。

建议给这一明确文案建立渠道适配分类，优先其他健康渠道；池整体繁忙时采用现有容量预算、退避和jitter，遵守Retry-After。可另纳入已核实的完整`service error, please try again later.`（新版2例）；不要把所有400、所有含retry的文本放行。内部错误400七例均在旧运行期，纳入回归样本但不作为新版故障计数。

现有容量重试3次、30–120秒，普通上游重试3次、5–15秒，总重试16、jitter20%。先补正确分类，不扩大总额度。参考[重试与抖动设计](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)。

### 参考图先本地下载校验再有限重试

27个参考图400全部保持hybrid、reference_retry_count=0。新版后的11个具体为：账号12“参考图无法读取”7个，账号32“参考图国内下载中转失败”2个，账号33“图床URL下载失败”2个。建议将这些已核实的输入素材错误交给已有local流程：本站安全下载并校验成功后，内联给另一个兼容渠道；若本地也证明链接失效、坏图或超限，则明确提示用户更新素材。

另16个旧运行期样本包括`reference image source download failed`和read tcp错误骨架，可补精确回归，不用任意download/timeout关键词替代执行阶段判断。对经常拉图失败的渠道或素材域名，可先行使用local；保留现有HTTPS、公网地址、重定向、字节/像素限制及下载并发门。

6个local下载超时已经参考重试2次，继续加次数收益不明。更合适的是按用户隔离的素材暂存、提交前校验可读性、缓存和同素材并发下载合并；持久化稳定素材快照，减少签名URL过期或源站波动。压缩、缩尺寸会改变素材，应设为用户可见的选择，不能静默修改。

### 上游已返回图片来源时只恢复结果下载

9个unknown全来自账号24，提交集中于北京时间10-29 **16:22:18至16:34:29**；均有上游succeeded尝试审计，本站下载返回HTTP502，没有Worker重排。样本`asyncimg_f92d7c865f4834444c75536099e72b86`从invoking直接进入unknown。

生产代码在结果下载失败时进入unknown，结果来源尚未进入可恢复持久状态，且下载与生成共用executionCtx。建议新增独立结果获取阶段：先保护性保存结果定位信息、上游request ID和固定账单标识；用独立小预算对同一结果URL作有限GET重试，再进入现有暂存/上传/计费流程。起始策略可设最多2次重取并带抖动，之后按真实恢复率和尾延迟调整。403/404先识别链接过期，有查询接口则刷新同一结果地址。

这类恢复不得重新生图、换号生成或重复扣费。其余3个账号32的504虽带参考图下载超时文字，但执行阶段未独立确证，保持unknown并优先对账。非幂等生成请求的自动重试须有未执行证据或上游幂等保障，见[HTTP幂等与重试语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)。

源码依据为生产提交的[Worker](https://github.com/JasonWangJie/sub2api_forimg/blob/634b8fdedf6e523a2e371878b5a0e1a20d4738eb/backend/internal/handler/durable_async_image_worker.go#L661)和[下载器](https://github.com/JasonWangJie/sub2api_forimg/blob/634b8fdedf6e523a2e371878b5a0e1a20d4738eb/backend/internal/service/async_image_protocol.go#L815)。当前没有实测重取这些历史地址，9个是覆盖范围而非承诺能追回的数量。

## 渠道与协议优化

- **渠道健康按模型与规格区分。**账号1有6,458条503/UNAVAILABLE失败审计，其中6,325个任务最终由其他渠道接续成功；最后相关失败为10-28 20:37:47。该账号当前已经不可调度，本次没有操作。建议恢复前小流量验证，并扩展现有熔断为账号/共享上游×模型×规格的失败率降权、短冷却和少量探测恢复。不要把内容拒绝计入渠道故障。
- **固定能力拒绝避免反复回原号。**`.60`已支持fileData/fileUri/file_id不兼容及参考图大小限制400/422，并允许池耗尽后Worker退避、软排除放宽回原号；这一行为不能套用旧版“永久硬排除”结论。固定模型/尺寸/传输不兼容应排除当前组合，临时处理失败才冷却后重试原号。优先配置已有model+resolution池，增补输入传输方式、图片张数、字节和像素能力。
- **33个无图响应与29个聊天文字先查协议。**前者集中账号12/32，后者账号2/3。核对真实图片模型映射、finishReason、安全字段、工具调用和附件结构；区分解析漏图、聊天模型误路由、明确未生成和上游已执行。确认没有生成且非内容拒绝时，再允许一次其他渠道；不能对任意无图响应自动再生成。
- **上游返回结构化错误。**统一错误阶段（输入、生成、输出获取）、稳定错误码、retryable、Retry-After及request ID；适配层保留这些字段。精确文本作为兼容兜底，避免持续追加句子仍漏判。日志只存安全结构摘要，避免聊天回复复述用户提示词。

`.60`已经有本地素材回退、换渠道、存储/计费幂等恢复、图片熔断。fileData25个与大小限制9个最终失败都在当前进程启动前，不能报告为新版仍未处理。新版processing样本已Worker重试3次，选中审计7次；502与容量耗尽样本也已用满3次预算，需要改善输入或供给，不是缺少重试。

### 结果持久恢复与资源预算

新增迁移[227_ZJ_async_image_result_fetch.sql](../backend/migrations/227_ZJ_async_image_result_fetch.sql)。来源URL及必要账务快照加密保存，嵌套账号凭据、API Key、用户密码/TOTP、代理认证等不进入快照；来源不会暴露于任务接口。任务从`invoking`到`upstream_succeeded`与来源快照在同一事务提交，原请求载荷清除；终结时图片暂存、准备账单、来源删除与事件同事务提交。提交结果不明确时先回读，固定账单标识为`client:async-image:<task_id>`，继续复用原存储intent和扣费幂等机制。

来源阶段保存用量输入、账号倍率、分组字段和计价时间；最终账单须在图片尺寸验证后准备并持久化。最终账单准备前的动态模型价格或用户分组倍率仍可能受管理配置变更影响，不能理解为来源返回瞬间已冻结全部价格；账单准备完成后的恢复复用同一账单命令。

| 预算 | 当前代码值及含义 |
|---|---|
| 实际生成HTTP调用 | 每任务最多16次，覆盖同号重试、换号及Worker重排；`selected`不再等于新任务实际调用数。旧无调用标记的选账号片段按一次保守计入 |
| 生成截止 | 从任务提交起30分钟，包含排队/跨Worker等待；仍遵守现有单次执行与账号超时，取有效较短期限 |
| 结果GET | 每张首次GET加最多2次重取，次数在GET前原子持久；408/425/429/5xx及明确读/网络临时错误可重取，5–10秒抖动并尊重Retry-After，等待上限5分钟 |
| 结果恢复有效期 | 加密来源24小时；每轮下载独立于生成deadline，按张数和下载超时分配，最多10分钟；已落库图片恢复时跳过GET |
| 输出资源 | OpenAI不超过请求张数且硬上限16张；Gemini多part硬上限16张；总结果128MiB。单张取下载配置与64MiB中较小值，未配置时32MiB；Base64解码前预检，恢复再次检查，不静默截断图片 |
| 结果终结 | 账单准备使用独立15秒预算，最多3次持久机会；暂时故障保留来源与图片，只恢复后处理；结果保存另作短时续写及提交结果核对 |

调用预算耗尽返回独立错误，不能重新当作普通502继续重排。结果恢复代码在[结果获取处理](../backend/internal/handler/async_image_result_fetch.go)和[结果获取仓储](../backend/internal/repository/async_image_result_fetch.go)，已有GET结果失败与未知生成保持不同路径。

### 本地素材请求快照

素材稳定性另有[本地请求快照](../backend/internal/handler/async_image_prepared_request.go)：仅对`ReferenceTransport=local`、有已校验参考图、构建后无远程输入的请求，在生成调用前加密替换现有`request_payload`。快照绑定任务ID、原请求哈希与模型，路径只接受Gemini Chat Completions或OpenAI Images Edits；body、JSON封装和最终密文分别不超过64MiB。编码膨胀导致超出范围时不新增快照，继续保留原请求流程；开始保存后发生加密/数据库错误则先停止生成，按现有参考图及总预算重排。持久化与安全事件同事务，CAS限定invoking及版本且不递增版本，提交结果不明确先回读核对密文。后续合格重试跨Worker或进程可直接使用相同提示词、模型、参数与图片字节，不再依赖原签名URL；原生multipart本来已保存原字节，无需重复快照。终态清理沿用`ClearRequestPayload`，不使未知执行自动可重放，也不建立跨用户共享素材库。

### 渠道健康与输入能力配置示例

仍沿用既有图片熔断设置。代码默认关闭，未配置时不自动改变默认开关；下面只是可审阅的示例，没有写入任何服务器或管理设置。管理端已保存的运行设置可能覆盖配置文件，实际启用值须以运行时设置为准。

```yaml
async_image:
  image_circuit_breaker_enabled: true
  image_circuit_breaker_failure_threshold: 5
  image_circuit_breaker_cooldown_seconds: 300
```

健康键区分同步/异步、模型、规格和账号；仅在明确配置同一`image_health_group`时跨账号共享健康。不凭IP、名称相似或诊断猜测共享拓扑。连续失败或完整近期窗口中失败比例达到阈值后冷却，冷却结束限制半开探针；其他规格成功和迟到成功不清除新熔断。完整已知service timeout400/internal422及容量故障可参与健康；内容拒绝、用户输入固定限制不计临时渠道故障。明确规格拒绝在精确模型/规格范围暂存5分钟能力缓存，避免单一规格污染整个账号。

半开探针持有到图片响应解析结束，不能仅凭HTTP200或请求张数推断恢复；活跃探针每10秒按所有权续租，完成即停止，进程退出后租期回收。OAuth内部恢复共用本次探针。健康写入使用独立2秒上下文，避免账号调用结束时的取消吞掉统计；Redis不可用仍沿既有放行策略。输入预筛发现渠道仅接受local且确认尚未发出任何生成请求时，hybrid任务可按原预算持久切换local；已发出请求或执行未知时不使用这一快捷回退。

账号创建/更新接口现有`extra`可使用以下可选片段；须保留账号其他已有extra字段。当前没有新增专用的账号配置表单，后端创建、更新与批量更新均校验这些字段。

```json
{
  "image_health_group": "provider-pool-a",
  "image_input_capabilities": {
    "transports": ["local", "passthrough"],
    "max_images": 4,
    "max_image_bytes": 20971520,
    "max_total_bytes": 41943040,
    "max_image_pixels": 25000000,
    "max_total_pixels": 50000000
  }
}
```

- 只有经过确认共享故障域的账号才使用相同`image_health_group`；不需共享时省略。值必须是无首尾空白、最多128字节的字符串。
- `local`表示构建后已内联或multipart的输入，`passthrough`表示仍有远程URL；`hybrid`是回退策略，不是能力数组值。混合输入只要有远程URL按passthrough判断，mask计入张数。
- 数值必须是非负整数，省略或0表示未声明上限。根据实际渠道能力填写，示例不是统一推荐限额。未下载远程素材的bytes/pixels为未知，不将未知当作超限证据；已知内联数据从构建后请求统计，不为预筛额外发网络请求。
- 这些字段只过滤不兼容候选，不改变模型、请求图片、质量或管理池；独立输入能力预筛不依赖熔断开关。跨任务学习仅缓存有明确证据的精确规格拒绝，不依据泛400猜测永久限制。

实现入口见[输入能力校验与筛选](../backend/internal/service/image_input_capabilities.go)、[健康策略](../backend/internal/service/image_account_circuit_breaker.go)和[Redis健康状态](../backend/internal/repository/image_account_circuit_breaker.go)。

### 运行稳定性与可观测性

- Redis队列领取异常采用指数退避、抖动及日志限频；恢复不重置持久的实际调用预算。
- 停机先停领取/维护，再等待已领取任务，保留执行和心跳，最长930秒后取消；本地[service模板](../deploy/sub2api.service)与[安装模板](../deploy/install.sh)设置`TimeoutStopSec=990`。这不会自动修改已安装的systemd单元。
- 默认定价JSON通过Go资源内嵌，在默认文件缺失时回退；管理员显式自定义路径仍按原错误处理，避免掩盖配置问题。
- 看板统计复用当前任务筛选和所有权，提供有真实调用标记任务的首试成功率、换账号/local/结果GET重取后的恢复率、当前unknown与历史unknown事件、调用数与选择数、成功任务P95/P99、队列/生成/后处理P95、最老排队时间；结果过期单列。生成耗时按首次进入调用阶段至上游成功，包含期间换号与重排等待，不等于纯上游HTTP耗时。账单实际成本聚合由接口提供，不等于已掌握上游供应商采购成本。无旧调用标记的数据不会伪装成准确首试样本。
- 新增失败事件保留阶段、稳定码和安全摘要；无图诊断只计结构、类型与finishReason，不保存完整回复、真实提示词或签名素材URL。历史事件未留原错的数据不伪造回填。
