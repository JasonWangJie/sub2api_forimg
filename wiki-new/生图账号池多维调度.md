# 生图账号池多维调度

## 目标与兼容边界

管理端 `/admin/groups` 的生图账号池支持三种互斥运行模式：

| 模式 | 持久化键 | 请求匹配 |
|---|---|---|
| `resolution` | `model=''` + `size_tier=1K/2K/4K` | 按解析后的清晰度 |
| `model` | `model=<精确模型 ID>` + `size_tier=''` | 按客户端请求模型 |
| `model_resolution` | `model=<精确模型 ID>` + `size_tier=1K/2K/4K` | 模型和清晰度同时精确匹配 |

迁移 `backend/migrations/225_ZJ_image_account_pool_modes.sql` 为 `groups.image_account_pool_mode` 设置 `resolution` 默认值。升级前的 `group_image_size_accounts` 行通过新增默认 `model=''` 原样保留，因此既有分组、新建分组和旧 1K/2K/4K 配置继续使用原行为。

三套绑定同时保存在原表中，切换模式只改变运行时使用的查找键，不删除非当前模式配置。关闭分组生图能力时管理端隐藏编辑区域，但仍提交已加载的完整配置；若配置加载失败，则普通分组字段可保存，本次操作不会用空值覆盖账号池。

## 管理接口

```http
GET /api/v1/admin/groups/:id/image-account-pools
PUT /api/v1/admin/groups/:id/image-account-pools
```

请求和响应主体：

```json
{
  "mode": "resolution",
  "resolution_pools": {
    "1K": [],
    "2K": [],
    "4K": []
  },
  "model_pools": [
    {
      "model": "gpt-image-2",
      "accounts": [{ "account_id": 101, "priority": 1 }]
    }
  ],
  "model_resolution_pools": [
    {
      "model": "gpt-image-2.5-sunburst",
      "resolutions": {
        "1K": [],
        "2K": [{ "account_id": 102, "priority": 1 }],
        "4K": []
      }
    }
  ],
  "model_candidates": ["gpt-image-2", "gpt-image-2.5-sunburst"]
}
```

GET 的账号项附加 `account_name`，并返回平台默认目录、账号映射目录及已保存模型合并后的 `model_candidates`。PUT 在一个数据库事务中更新模式并全量替换三套绑定；账号可独立于 `account_groups` 绑定，但必须存在、未删除且平台与分组兼容。

旧接口继续保留：

```http
GET /api/v1/admin/groups/:id/image-size-accounts
PUT /api/v1/admin/groups/:id/image-size-accounts
```

旧 PUT 只删除并重建 `model=''` 的清晰度行，不修改当前模式，也不删除模型或模型+清晰度行。分组复制会在同一事务内复制当前模式和全部生图账号池绑定；分组或账号删除仍由外键级联清理。

## 模型键与调度规则

- 模型键取客户端请求侧 ID，先去除首尾空白，再区分大小写精确匹配；账号 `model_mapping`、渠道映射和 Composite 上游映射只参与后续兼容性过滤，不改变账号池归属。
- 模型 ID 必须是有效 UTF-8，最多 255 字节，不能是空值，不能包含控制字符或 `*`。
- Gemini 原生路径使用路由中解析出的裸模型 ID，不把 `models/` 路径前缀写入池键。
- 当前模式所需维度缺失，或精确键没有任何绑定时，使用分组原 `account_groups` 默认池。
- 精确键存在绑定后，即使其中账号因平台、状态、过期、限流、模型支持、熔断或本次 failover 排除而全部不可用，也返回无可用账号，不跨池回退。
- 池内绑定 `priority` 覆盖账号默认优先级；同优先级继续使用有效负载、实时负载和 LRU 均衡。

接入范围与迁移前清晰度池保持一致：OpenAI 专用图片生成/编辑、OpenAI/Gemini 持久异步 Worker、Gemini 原生与 Gemini 兼容生图入口，以及这些入口中的 Composite 调度。OpenAI Responses/WS、GPT 图片模型的 Chat Completions 工具路径和 Gemini 批量生图没有接入该路由上下文，选号行为保持原样。

支持的分组平台为 OpenAI、Gemini、Antigravity 和 Composite，不包含 Grok。

## 管理端操作

编辑分组并开启图片生成后，可在“生图账号池调度”中选择三段式单选：

- 按清晰度：填写 1K、2K、4K 三个账号池。
- 按生图模型：从候选列表搜索或手工输入精确 ID，每张模型卡片填写一个账号池。
- 模型 + 清晰度：每张模型卡片分别填写 1K、2K、4K。

账号输入支持 `101, 102:1, 103:1`。没有写优先级时按输入顺序生成优先级；重复账号在同一池内去重。删除模型卡片只删除当前模式中的该模型，另一模型模式和清晰度模式配置不受影响。

## 冒烟复核与计费边界

- 账号池只负责缩小候选账号集合及覆盖池内调度优先级，不参与价格计算。最终账号的计费倍率字段会完整保留，分组图片价格、独立图片倍率、用户/高峰/全局倍率以及同步/异步结算仍走既有链路。
- Gemini 原生和兼容请求的像素尺寸按短边映射 1K/2K/4K，与 Gemini 图片计费一致；例如 `1792x1024` 同时路由和计费为 1K。OpenAI 专用图片接口继续使用其原有长边/请求档位规则。
- 独立池不能绕过 OAuth-only 分组：管理接口拒绝写入 API Key 账号；若分组之后改为 OAuth-only，运行时会再次过滤。精确池因此变空时仍封闭失败，不会越池。
- Antigravity 分组只接受 Antigravity 账号；Gemini 分组仍允许 Gemini 账号，以及满足运行时混合调度条件的 Antigravity 账号；Composite 再按请求目标平台过滤。
- `/antigravity/v1beta` 生图请求即使沿用强制平台入口的权限/并发旁路，也会建立图片意图、账号池、计费和熔断上下文，并用当前池而非默认池判断单账号 503 退避。
- 渠道别名可用于识别其映射后的 Gemini 生图模型，但池键仍是客户端请求的原始精确 ID；模型候选列表不展示不能保存的通配 ID。
- 迁移 225 在添加三个新命名约束前先执行 `DROP CONSTRAINT IF EXISTS`，可以在失败重试或迁移审计环境中重复执行，而不会因约束已存在而中断。

## 验收重点

1. 先在隔离数据库执行到迁移 222，写入旧清晰度绑定，再升级到 225，确认绑定数量、优先级与 `resolution` 默认模式不变。
2. 分别验证三种模式的精确键、缺配置回退和已配置不可用时封闭失败。
3. 用客户端别名、渠道映射和账号模型映射验证池键仍采用请求侧模型，而后续模型支持过滤仍采用现有映射规则。
4. 验证旧清晰度 PUT 不删除两类模型行；验证分组复制保留模式、模型、清晰度和 priority。
5. 登录管理端检查亮色/暗色、键盘单选/添加、窄屏卡片布局、关闭再开启生图后的配置保留。
